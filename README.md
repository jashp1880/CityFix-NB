# CityFix NB — AI City Problem Detector

A functional React/Vite + FastAPI MVP for community-maintenance reports in New Brunswick and Rutgers. Independent project; not an official municipal or university service.

## Features

- Register, sign in/out, edit profiles; Argon2id password hashing and expiring JWTs in HttpOnly cookies. Database-backed session revocation on logout. Admin privileges are never granted through public registration.
- Submit a JPEG/PNG/WebP photo (5 MB, 20 megapixel limit), title, description, category, severity, location, jurisdiction and map pin. Photos are decoded, resized and re-encoded without EXIF metadata.
- Public dashboard with OpenStreetMap/Leaflet map, search, category/status/severity/area filters and pagination; personal report dashboard.
- Admin review, public status notes, complete history, and explicit routing-recommendation approval. **There is no email, phone, or department-contact automation.**
- Optional Gemini image classification and description suggestions. Sending a photo requires consent; suggestions require explicit application and final user confirmation. Missing/provider-failed AI returns an honest unavailable response and manual entry remains usable.
- Duplicate warnings using category, geographic distance, exact cleaned-photo hash and perceptual image similarity. Residents must acknowledge possible duplicates. These are suggestions, not definitive matches.
- Private Supabase Storage or S3-compatible bucket with short-lived signed image URLs. Never put a service key into Vite variables.
- Origin checks and custom-header CSRF protection, explicit CORS allowlist, request/upload limits, validated input, database-backed submission/login/AI limits, security headers, and public responses without account identifiers.
- Automated API and React interaction tests and GitHub Actions, including PostgreSQL integration testing in CI.

## Local development

Requires Python 3.12 and Node.js 22 or newer. From the repository root:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r backend/requirements.txt
cd backend
cp .env.example .env
# Set JWT_SECRET to a freshly generated value of at least 32 characters.
# Generate locally: python -c "import secrets; print(secrets.token_urlsafe(48))"
# Keep that value in .env only; never commit it.
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

In a second terminal:

```sh
cd frontend
npm ci
npm run dev
```

Open http://localhost:5173. Vite proxies `/api` and development-only image URLs to FastAPI. Local development uses SQLite and local uploads only; production explicitly refuses SQLite and never falls back to ephemeral uploads.

## Tests

```sh
cd backend
python -m pytest -q
cd ../frontend
npm test
npm run build
npm audit
```

Set `TEST_DATABASE_URL` to a disposable PostgreSQL database to run the API suite against Postgres. Tests **drop all application tables in that database**. Never point it at real data. GitHub Actions creates a dedicated ephemeral database for this purpose. AI tests stub the external provider; a real model requires configured access and separate live verification.

## Production setup — free tiers only

1. Create a **free** Supabase project for PostgreSQL and storage. Free projects have quotas and may pause after inactivity. Render's free Postgres expires after 30 days, so it is deliberately not provisioned as the persistent production database.
2. Create private bucket `cityfix-reports`, with a 5 MB object limit and `image/jpeg` allowed MIME type. Do not add public read/write policies. Signed URLs are issued only by the backend. Use the database's TLS-enabled session pooler connection URI with the owner credentials. Do not expose database or service-role credentials in the browser. The API enables RLS on its public-schema tables on initialization, with no anonymous Data API policies.
3. Import the repository's `render.yaml` into the intended Render workspace. It specifies a **free** Python web service. Set `DATABASE_URL`, `FRONTEND_ORIGINS`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`; `JWT_SECRET` is generated by Render. `STORAGE_BUCKET=cityfix-reports`. Keep `ENVIRONMENT=production`. No paid disks or databases are requested.
4. Alternatively configure a private S3-compatible bucket with `STORAGE_ENDPOINT`, `STORAGE_REGION`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, `STORAGE_BUCKET`. Give the key only PutObject/GetObject access for the `reports/` prefix. Do not use local disk in production.
5. Deploy `frontend/` to Vercel (Vite, `npm ci`, `npm run build`, output `dist`). The `/api/:path*` rewrite in `frontend/vercel.json` targets the provisioned `https://cityfix-nb-api.onrender.com/:path*`. Keep Vite's default `/api` base. A same-origin rewrite keeps session cookies first-party; directly calling an unrelated Render origin can fail in browsers that block third-party cookies. If you fork this project, update the rewrite to your actual backend URL.
6. Set `FRONTEND_ORIGINS` to the exact Vercel production origin. For local development or approved previews add explicit comma-separated origins. Wildcard credentials/origins are not allowed. The browser must send `X-CityFix: 1` on writes.
7. Optional AI: set `GEMINI_API_KEY` on Render from a **free-tier-only** Google AI project; `GEMINI_MODEL` defaults to `gemini-2.5-flash`. Do not enable billing without owner approval. No AI provider account or paid usage is automatically provisioned.
8. After registration and independent verification of the owner, run `python -m app.admin owner@example.com` in a trusted backend console to grant admin access. Do not grant it based solely on an unverified signup email.
9. Verify `/health`, register/login, photo submission/storage, map filters, personal dashboard, admin status history, logout revocation and the actual AI provider through the public URLs before announcing deployment complete.

API documentation: `/docs`. Health/configuration availability: `/health` (no credentials returned).

## Limitations and operations

- MVP uses initial SQLAlchemy table creation, not versioned migrations. Add reviewed Alembic migrations before changing a deployed schema.
- Registration has no email verification or password recovery yet. Rate limits are basic fixed windows; review abuse controls before a broad public launch.
- Public posts are immediately visible and include their selected location. Residents must avoid faces, license plates and private information. Add a moderation queue, takedown process, retention policy and recovery/backup plan for production operations.
- Department routing is based on the resident-selected jurisdiction and should be verified by a human. County/state roads, utilities and private property may have different owners. Rutgers source: https://ipo.rutgers.edu/university-facilities/operations-services ; New Brunswick source: https://www.cityofnewbrunswick.org/ . Recommendations are not official work orders.
- Map shows the current filtered page (up to 12 reports). Personal dashboard currently returns the latest 200 reports. Signed photo links last five minutes; reload to refresh them.
- Render's free service can sleep. Free database/storage/AI plans have quotas and availability limits. No uptime guarantee, paid resources or spending authorization is assumed.
- Database-backed rate buckets need periodic cleanup as usage grows. Failed transactions after cloud upload may leave an orphan object; add scheduled reconciliation and retention rules before scale.
- Automated tests cover mocked AI/storage boundaries plus local image storage. Real cloud credentials, production cookies, live AI and PostgreSQL deployment still require live checks.

## Secrets

`.env`, `.vercel/`, local databases, uploads, virtual environments and build artifacts are ignored. `.env.example` files contain variable names only. Never commit a JWT secret, database password, provider key or service-role key. Use provider environment-variable controls and rotate any accidentally exposed value immediately.
